## 二、★★★ 一个会让**所有规则永不命中**的 bug

附录 D.1 写明 `any_of` / `none_of` 是**可省略**的。我最初实现成：

```python
a = eval(all_of)      # 省略时 → True
b = eval(any_of)      # 省略时 → False   ← 错
n = eval(none_of)     # 省略时 → True
matched = a and b and n# ⇒ 恒为 False
```

**后果**：任何没写 `any_of` 的规则永远不命中。而且**不报错**——
所有谓词都是 `True`，日志上看「条件都过了却不触发」，极难定位。

正确语义（已按附录 D 修正）：

| 情况 | 语义 | 理由 |
|---|---|---|
| 省略 `all_of` | True | 无硬性约束 |
| 省略 `none_of` | True | 无排除项 |
| **省略 `any_of`** | **True** | ★ 不是 False |
| 显式写 `any_of: []` | True | 同上，「无附加要求」 |

变异测试确认：把这一行改回 `b = _eval_group(...)` → **14 条测试立刻失败**。

## 三、★★ 布尔谓词被当数字比较，导致风控静默失效

`_p_limit_up` 返回的 `actual` **已经是布尔结论**（`次数 >= N`），
框架又拿它去和阈值 `1` 比 `>=`。而 `_num()` 对 bool 返回 `None`
（原本为避免 `True == 1` 这类误判），于是：

```
limit_up: actual=False, op=">=", thr=1 → 无法比较 → 判 False + warning
```

结果上也是 False，所以**测试用「值对不对」根本发现不了**——
错的是**原因**：UI 显示「数据缺失」，把风控失效误诊成数据问题。

修法：引入 `BOOL_PREDICATES` 声明这类谓词自带结论，框架见到 `op="_bool"`
直接采纳，不再比较。

同类问题还有 `is_st`：`actual=False` vs `thr=True` 也走数值路径。
已修 `_cmp`：任一侧是 bool 时走布尔相等比较。

**测试怎么才算真阳性**：断言 `pred.missing is False` 且 `pred.error == ""`，
而不是只看 `value`——只看值的话，修与不修结果一样。

## 四、★★ `vol_ratio` 的分母含了当前这根，暴量检测永远不会触发

```python
window = self.volumes[-n:]   # ← 含当前
avg = sum(window) / n
return window[-1] / avg
```

单根暴量会被自己的分母摊平。N=5、当日量是平常 50 倍时：

```
50 / ((4×1 + 50)/5) = 4.63   ← 达不到 vol_ratio_max = 5
```

**理论上限是 N/(N-1) ≈ 1.25**（N=5），所以任何 >1.25 的暴量阈值形同虚设。

改为 `self.volumes[-(n+1):-1]`（分母排除当前）。
修复后同一场景比值 ≈ 47.6，正常触发。

> 这里还有第二个坑：写 `v[-n-1:]` 会取到 n+1 根、仍含当前。
> 必须用 `v[-(n+1):-1]` 才真正排除。已由测试锁死。

## 五、★★ custom 表达式：静态检查不能被运行期报错「冒充」

`x['__builtins__']` 在 AST 阶段是合法 Subscript，我的第一版测试：

```python
with pytest.raises(ValueError):
    safe_eval("x['__builtins__']", {"x": {}})
```

**这个测试是假阳性**——`{}` 是空的 dict，`.get()` 行为正常，
真正拦住它的是 `DANGEROUS_KEYS` 静态检查还是运行期 `KeyError`，
我没分辨。用 `{"x": 1}` 试才发现：抛的是
`TypeError: 'int' object is not subscriptable`——
**表达式本身就执行不了**，换成 `{"__builtins__": {...}}` 就能执行。

**危害**：这种假阳性会让「静态检查已生效」这个结论被推翻时无人察觉。
已改为断言 `match="敏感名"`（检查点专属消息）+ 用可执行对象做输入
（`test_dangerous_check_is_not_just_runtime_error`）。

同时 `safe_eval` 现在把**所有运行期异常**归一成 `ValueError`，
否则 `except ValueError` 抓不到 `KeyError`，危险表达式会**通过校验**
却在引擎里崩（典型的「校验通过但运行失败」）。

## 六、其他设计要点

- **`StrategyContext` 一次性备齐因子**，策略不自己查库。
  这是「所有因子取自同一 `as_of`」唯一可靠的保证（附录 D.3 第 4 条）。
  派生指标（`ma` / `vol_ratio` / `pct_change_n` / `crossed_above`）都是纯函数。
- **数据不足返回 `None`，绝不返回 0**。`ma(20)` 在只有 2 根 K 线时返回 `None`，
  由框架判 False + warning。`0` 是合法值（「今天没涨停」），不能当缺失。
- **`chan_signal` 不指定 `level` 时不按强度过滤**。M8 实测 strong/weak 胜率差
  66 个百分点（86.2% vs 20.0%），悄悄把 weak 混进买点是危险的。
- **不短路求值**：三个子句的谓词全部求值并记录，
  否则 UI 上会出现「为什么只看了一个条件」而无法排查。
- **参数指纹**（`param_hash`）供附录 7.2 的参数版本冻结使用。
- **`risk_note` 强制有值**。即使「不推荐」也要说清原因：
  仅有弱级别买点时，提示「弱买点不算买入信号，需等回抽确认后的 strong 三买」。

## 七、回测引擎：现金守恒是唯一的生死线

### 7.1 ★★ 我在现金守恒上错了两次，都是「看起来有收益、权益为负」

**第一次**：买入时只扣成本、不扣成交额 → 现金几乎没少，权益虚高。

**第二次**（更隐蔽）：平仓时
```python
cash += net_pnl      # net_pnl = 卖出净额 - 买入总额 - 买入成本
```
而入场时**已经扣过**「买入总额 + 买入成本」了 —— 等于重复扣一次。
实测：10万本金做一笔平价交易后只剩 **8986 元**（-91%）。

正确算法：
```
入场：cash -= 买入成交额 + 买入成本
平仓：cash += 卖出成交额 - 卖出成本      ← 只加回卖出净额
单笔盈亏：net_pnl = 卖出净额 - 买入总额 - 买入成本   （另一个概念，用于胜率统计）
```
**两者不可混用**：`cash` 守恒 vs `net_pnl` 相对本笔本金。

### 7.2 ★ 循环边界写成 `i < len(bars) - 1` ⇒ 未平仓持仓被静默丢弃

`eod` 强平永远不触发，最后一根从未被访问。
设`max_hold=None` 时一笔交易都不记录 —— **收益虚高且无任何报错**。

### 7.3 ★ 入场信号不能复用为出场信号

早期让 `entry_fn` 兼任出场信号，结果「逢 K 线就买」的策略
在**同一根 bar 上买入又卖出**，无限 churn，成本吞掉一切。
已拆成 `exit_fn`（止盈止损/最大持有）与 `exit_signal_fn`（反向信号）。

另外**引擎内置 `max_hold_days` 判定** —— Entry 里带了该字段却不生效，
等于策略可无限期持仓，收益率脱离实际。

### 7.4 入场价口径：不提供「按信号价成交」的选项

M8 实测同一批信号按信号价胜率 99.5~100%、按收盘价只有 86~91%。
引擎只接受「信号日之后的日期 + 该日价格」，并额外叠加滑点。
想作弊至少得先过`entry_date < 信号日` 的校验（计入 `skipped`）。

### 7.5 成本模型

佣金万2.5 + 印花税万5（**仅卖出**）+ 滑点单边 0.2% + 单笔最低佣金 5 元 + 整手 100 股。
一轮完整买卖约 0.5~0.9%。`cost_drag_pct > 30%` 说明策略在给券商打工。

### 7.6 ★ 自动定权的顺序不能错

```
1. 只在**前段训练窗**搜参数组合
2. 训练窗成交 < 10 笔的组合直接剔除（3 笔赚 20% 是运气）
3. 取训练最优的一组，再看它的**样本外**表现
4. 样本外不达门槛 → 该组不可上线（oos_gate 明确指出不达标项）
```
**绝不能「遍历所有组合、看哪个样本外最好」** ——
那样样本外就变成了训练集，等于什么都没验证。

`oos_gate` 门槛：折数 ≥3、样本外成交 ≥10 笔、累计收益 > 0。
不达标时必须说清是哪一项（`oos_reason`），不能只说「不通过」。

## 九、★★★ 真实回测暴露的三个胶水层bug

回测引擎本身没错，错在「把缠论信号翻译成回测信号」这一层。
这三个 bug 有一个共同特征：**都不会报错，只会给出很差的收益**。

### 9.1 信号被重复计入 → 成本拖累飙到 156%

`scan_signals` 返回的是**结构区间内的历史信号**：同一个 3buy
（标记日期 2025-12-31）在之后连续几十天每根 bar 都「出现」。
不判新鲜度就会在同一信号上反复建仓、每次都付成本。

### 9.2 ★ 判新鲜度**不能**用 `s.date == 当日`

信号标记的是**笔的结束日**，而笔要等下一根 K 线才能确认 ⇒ 天然滞后。
实测 000001 扫描 190 天，`s.date == 当日` 命中 **0 次**；
改成「本日新可见」（上次扫描没见过、本次第一次见）后才有 189 次。

我先修成 `s.date == 当日`，结果成交数直接掉到 **0 笔**——
若没核对「0 笔」意味着什么，会误判成「策略没有信号」。

### 9.3 entry 与 exit 各自扫描 → 同一天买卖

两个函数各扫一遍，对「什么是新信号」判断不一致，
出现「09-22 有新买点 → 09-23 开盘买入 → 当天被新卖点平掉」。
修法：`_scan_new` 作为**单一扫描点**，同时产出买卖点并更新 `seen`，
再用 `shared` 缓存本根结果供 exit 复用。

效果：胜率 25%→40%，平均持有 5.0→14.2 天。

### 9.4 一个不是 bug 的「异常」

000007 在 2026-07-07 出现 -30.99%：当天开盘 13.50（**涨停价**，
前收 12.88），盘中一路跌到跌停 11.59 收盘。
开盘价真实可成交，按开盘买入 -31% 是**如实反映市场风险**。

⇒ 只挡「封死的一字板」（O==H==L），**不挡**「开盘涨停收盘跌停」。
后者是能成交的，挡掉反而是失真。

### 12.1 C（主路径）：系统不自动卖出

`overlay.py` 输出的三类标注，**没有任何一个是卖出指令**：

`python -m backend.domain.overlay` 的自检会打印：

✓ 卖点标记为 advisory=True（提醒）

### 12.2 A（风控）：给三个止损位，不替你选

`stop_references()` 一次给全三种取法，各自说明代价：

| 取法 | 信号意义 | 特点 |
|---|---|---|
| `zhongshu_low` | 破中枢下沿 | 结构转弱，幅度适中（缠论常用） |
| `prev_bi_start` | 破前一笔低点 | 信号最强，幅度可能偏大 |
| `atr` | 入场 -2×ATR | 波动率自适应，震荡市易被反复触发 |

**为什么不给单一值**：选哪个取决于你能承受多少回撤、以及个股波动特征。
系统把三个摆出来，说明各自代价，由你选 —— 这是 C 方案的延伸。

## 十四、★★★ D14：止损锁定 5% + 样本外验证（关键负面结论）

用户 2026-10-09 08:25拍定：**止损 5%，并做样本外测试。**

### 14.1 ★★ 样本外验证不能用 `walk_forward` —— 会得到假结论

`backtest.walk_forward` 把 bars **切片后独立重跑**，隐含假设
「entry_fn 只依赖片段内数据」。但缠论信号依赖：

1. **长历史**（实测 190 天才扫出 189 个信号）
2. **连续的 `seen` 集合**（判断信号是否「新可见」）

实测后果：train=120 / test=30 的切片重跑后，成交从 **2 笔掉到 0 笔**
——片段只有 30 根，而 `warmup` 就要 60 根。
用它做缠论的样本外验证会得到「样本外 0 笔 ⇒ 无法验证」的**假结论**。

**正确口径**：全样本连续跑（缠论结构与 `seen` 都保持连续），
**只统计入场日落在样本外区间的成交**。
已写入 `scripts/run_oos.py`，并由 `test_does_not_use_walk_forward_slicing`
与 `test_trades_kept_continuous` 双重守护（后者断言 `entry_fn`
每次都收到完整 200 根，而非切片）。

### 14.2 ★★★ 样本外结果随样本量震荡 —— **没有稳定优势**

| 超额 | +2.88% | +2.77% | +1.52% | +1.76% | +1.46% | +1.45% |
| 门槛 | 通过 | 通过 | 通过 | 通过 | 通过 | 通过 |

**6/6 通过，但增益只有 +0.10 ~ +0.43pp**，
且 `up` 门控把**胜率从 32.0% 砍到 18.8%**、平均收益从 +0.44% 降到 -0.81%。

⇒ 门控本身是稳定的，但增益远小于 D14 观察到的震荡幅度，
**不足以支撑上线决策**。若要选，`no_flat`（避开震荡市）更合理：
超额 +1.47%、胜率 32.4%（不低于基线），代价最小。

### 18.4 ★★ 前视偏差的代价：同口径对照才量得出来

| 口径 | 笔数 | 样本外超额 |
|---|---|---|
| 因果（可用） | 543 | +1.56% |
| 段标签（含未来） | 502 | +1.80% |

代价 **-0.24pp**。

★ **第一版我直接拿两个门控比超额，得出「前视反而更好」的荒谬结论。**
原因：两者选的根本不是同一批日子（Jaccard 84.9%），
差值混了「门控口径差异」而非「前视的收益」。

正确口径：**锁定同一批 `up_dates`**，只改「判定依据」是否含未来。
已由 `test_leaky_is_stricter_than_causal` 守护（`leaky` 允许的日期必须是
`causal` 的子集，不会反向套利）。
