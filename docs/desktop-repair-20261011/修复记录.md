## 查明的问题与修复

1. **打包漏文件导致黑屏**：实际 0.2.0 的 app.asar 只有主进程 JS 和图标，没有 shell.html/css/js。补齐 files，并增加 afterPack 对真实 asar/运行时/后端/数据库的检查，漏件即构建失败。
2. **桌面自解压启动慢**：桌面原文件是 180,426,865 字节的 portable 自解压程序，实际进程在 Temp 目录运行。新快捷方式直接启动已部署程序，免去每次展开应用。
3. **Python 路径不匹配**：主进程指向 runtime/python.exe，原包只有 runtime/Scripts/python.exe。统一支持布局，并构建真实独立 Python 运行时。
4. **旧 runtime 不独立**：原 pyvenv.cfg 的 home 指向 WorkBuddy Python。新增 build_standalone_runtime.py，校验 sys.base_prefix、标准库和全部关键第三方模块均来自新 runtime-standalone；原 runtime 保留。
5. **窗口启动前阻塞**：同步 execFileSync 导入依赖，最多阻塞主线程 20 秒。先加载并显示启动页，再异步启动；首屏避免重复加载 Python 依赖。
6. **就绪探测错误**：旧探测把 404 等响应也当成功，并用需要数据库扫描的 /api/health 阻塞启动。新增轻量 /api/ready，必须匹配 service、ready、root，数据健康仍由 /api/health 独立提供。
7. **进程生命周期**：修复重复启动竞争、退出菜单绕过清理、未等待 taskkill 完成及旧进程 exit 回调覆盖新进程状态。重载网页不重启 Python，关闭窗口保留托盘，再次启动唤醒原实例。
8. **失败仍须可见**：运行时缺失、端口冲突、导航失败、渲染进程退出显示诊断；即使启动页本身缺失，也有不依赖外部文件的内联诊断页。
9. **并发查询串扰**：端到端测试出现概览 API 偶发 500。用确定性双线程测试复现原共享 DuckDB 连接的结果被另一查询消耗（SELECT 101 的结果变为 None），改为每线程独立 cursor；显式释放会关闭相应游标。未修改交易算法、品牌内部标识或库名。

node -e 'const b=require("C:/tmp/opbuild/node_modules/electron-builder"); b.build({projectDir:process.cwd(),targets:b.Platform.WINDOWS.createTarget("dir"),config:{electronDist:"C:/tmp/opbuild/node_modules/electron/dist",directories:{output:"../release/Opus-0.2.1"}}}).catch(e=>{console.error(e);process.exit(1)});'
