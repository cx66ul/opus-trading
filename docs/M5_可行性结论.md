# Hawk · M5 板块数据可行性结论（2026-10-08 实测）

## 结论：板块成分股在当前网络下不可得，M5 需降级实现

---

## 二、成分股完整列表：三重阻碍

### 阻碍 1：分页是 AJAX 的，URL 参数无效
同花顺成分表每页 20 条，半导体板块共 **10 页**（`.page_info` 显示 `1/10`）。
翻页控件 `a.changePage[page="2"]` 的 href 全是 `javascript:void(0)`。
**我最初以为 URL 形如 `detail/field/.../page/2/code/xxx/`，实测确实能发出该请求，
但页面不更新** —— 说明服务端有校验。

### 阻碍 2：反爬 JS 挑战
即使带上 `Referer` 与 `X-Requested-With`，AJAX 端点仍返回 **401**：
```html
<script src="//s.thsi.cn/js/chameleon/chameleon.1.7.min.js"></script>
<script>window.location.href="//q.10jqka.com.cn/..."</script>
```
`chameleon.js` 是同花顺的反爬挑战脚本，纯 HTTP 无法通过。

### 阻碍 3（决定性）：Nginx 层 IP 限制
在浏览器页面上下文里发同源 `fetch`（自动带 Cookie、通过 JS 校验）：
```
HTTP 403  Nginx forbidden.  request info: 183.67.45.146
```
**这是服务端按 IP 段做的限制，不是技术问题。**
换网络环境（校园网/移动热点）有可能解决，但不确定。

## 三、东财 `hybk` 字段能否替代？—— 不能

涨停池的 `hybk`（行业）字段实测可用，43 条记录带 32 个不同行业
（专用设备、光伏设备、化学制药、白酒、电池、航运港口……）。

**但覆盖度只有 42/5571 = 0.75%** —— 它只标注涨停股，
而板块强度需要**全部成分股**的数据。两者差距是两个数量级。

## 四、M5 降级方案（推荐）

### 方案 A：用「行业关键词 + 股票名」做近似归类（可立即实施）
- 数据：本地 5571 只股票名 + 已实测的板块清单（451 个）
- 方法：建立「板块名 → 关键词」映射（如「电池」→ 电池/锂/储能），
  用股票名与全市场个股涨幅做匹配归类
- **局限**：准确率有限（股票名不含行业信息），板块边界不精确
- **诚实标注**：这会让板块强度成为「粗粒度参考」而非精确计算

### 方案 B：换网络环境复测（推荐先试）
- 你在校园网/移动热点下跑一次 `python scripts/fetch_board_members.py --probe 881121`
- 若拿到 > 100 只，则全量抓取（451 个板块约需 30~50 分钟），方案 A 就不必做

### 方案 C：暂缓板块强度，先做市场状态机
- 六态状态机（附录 4.7）所需数据**全部已实测可用**：
  涨停家数、跌停家数、炸板率、最高连板高度、昨日涨停溢价
- 这部分是 M5 里最有决策价值的，且不受成分股问题阻塞

## 六、我的建议

**先做「六态市场状态机 + 情绪指标」**（数据齐备、决策价值最高、不受阻塞），
同时你抽空换网络试一次方案 B。若成分股能拿到，再回头补板块强度。

理由：市场状态机回答的是「现在该防守还是进攻」，
而板块强度回答的是「买哪个板块」—— 前者更宏观、更刚需，
且当前数据已100% 具备，没有理由被成分股问题连带阻塞。
