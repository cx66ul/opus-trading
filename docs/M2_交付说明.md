## 一、重大发现：省掉了浏览器依赖

提示词原计划用 **Playwright 抓金十数据**。实测发现**新浪 7×24 提供结构化 JSON API**：

```
GET https://zhibo.sina.com.cn/api/zhibo/feed
    ?page=1&page_size=20&zhibo_id=152&tag_id=0&dire=f&dpc=1
→ 200application/json，约 28KB
```

| 源 | 状态 | 说明 |
|---|---|---|
| **新浪 7×24** | ✅ 纯 HTTP 可用 | 结构化 JSON，30~50 条/页，含标签与关联标的 |
| 金十 jin10 | ⚠️ 需Playwright | SPA 骨架页，`flash-api` 返回 502，参数在 JS 运行时生成 |
| 财联社 cls | ⚠️ 需 Playwright | 网页与 API 均 JS 渲染；3 种参数组合全部 404，HTML 内检索 API 线索 **0 次** |

**没有猜 API 参数**（第十二章：不许猜、不许编造）。金十/财联社改为「Playwright 探针 + 明确报错」。

### 三源结构（D4 强制冗余已满足）
- **sina_7x24** — 主源，纯 HTTP，已实测 30 条/页
- **jin10 / cls** — 冗余源，探针已实现（`Jin10ProbeSource` / `ClsProbeSource`），待 Playwright 环境
- **关键设计**：需浏览器的源**明确抛 `NotImplementedError`**，绝不静默返回空
  —— 静默空会让调度层误判「今天没消息」，是最危险的失败模式

## 二、铁律三落地：抓取与解析严格分离

```
消息源 → raw_news(原样落盘, parsed=0) → [异步] LLM打标 → news(结构化)
         └─ fetch_news.py                    └─ parse_news.py
```

分离的收益（都是实测驱动的设计，不是理论）：
1. 改prompt / 换模型时**不必重抓** —— 免费源有频次限制，重抓可能触发封禁
2. **原文可审计** —— LLM 打「利好」时可回看原文，判断是模型误判还是消息本身模糊
3. **支撑 D6 复盘** —— raw_news 保留报文全文，任何时候都能重跑解析

| 脚本 | 职责 | 绝不做的事 |
|---|---|---|
| `scripts/fetch_news.py` | 抓取 → raw_news | 不解析、不判断、不打标 |
| `scripts/parse_news.py` | 消费 raw_news → news | 不发起抓取 |

## 三、LLM 打标（D2：只用本地 7B）

模型：`qwen2.5:7b-instruct-q4_K_M`（4.7GB，适配 RTX 5060 Laptop 8GB 显存）

### 三层防护（均已实测）
| 层 | 作用 | 实测案例 |
|---|---|---|
| JSON 提取 | 花括号配平法，非正则 | 能处理 ```json 围栏、前后夹带文字、含`}` 与转义引号的字符串、截断输出 |
| 输出校验 | 非法值一律兜底 | `direction:"暴涨"`→neutral、`strength:99`→夹到5、`"强"`→1 |
| **代码本地化** | 防幻觉（附录 4.6） | 输入 `[600519, 999999, "宁德时代"]` → 仅保留 600519 |

其他关键设计：
- **温度固定 0** —— 打标要可复现
- **规则兜底不丢消息** —— LLM 不可用时返回 `neutral/strength=0` 并标记 `*_fallback`，
  使下游能区分「已分析但无关」与「没分析过」
- **记录 `prompt_ver`** —— 便于回溯「当时用什么打的标」

### 实测数据
- 40 条真实快讯已抓取入库
- **源自带关联仅 2/30 含 A 股** → 印证「消息→个股」必须靠 LLM 推断 + 同板块校验（M3 核心工作）

### 开发中修复的 3 个真实缺陷
1. **`ext` 字段是 JSON 字符串而非 dict** —— 实测 50/50 全是 str，直接 `.get()` 会崩
2. **LLM 输出的 `created_at` 用了系统时间** —— 被纯函数测试抓到，违反铁律二；
   改为 `as_of` 必填（不给默认值，让违规在调用时暴露而非静默退化）
3. **纯函数检查器本身有两处误报** —— 注释/文档字符串里的说明文字被判违规；
   改为 AST 递归剥离 docstring 并跳过 `__main__` 块，且做了反向验证确认能抓真违规
