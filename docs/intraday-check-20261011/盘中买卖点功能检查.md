# 自选股盘中分钟 K 线买卖点检查

检查日期：2026-10-11（周日）。本次为代码、当前运行接口、数据库、界面与历史前缀回放检查，不声称已经完成交易日实时验收。未修改策略、图表或采集流程。

结论：已有日线历史买卖点标记，但尚不能在交易日盘中分钟 K 线上持续显示可及时使用的买卖点提示。

## 已有功能

自选股点击进入个股详情，当前 `/api/stock/{code}` 读取 `kline_daily`，按所选交易日 15:00 调用 `chan.analyze`。图上有 B/S 标记、中枢、信号理由与启发式置信分数；卖点为提醒，不执行交易。界面只画最后 120 根日线，信号列表可包含更早历史。没有分钟周期选项或分时走势入口。

## 缺失环节

1. 分时走势和 1/5/30 分钟周期接口、分钟图展示及自选联动。
2. 当前桌面生命周期只启动新闻与邮件服务，未启动实时行情采集。已有 realtime 任务采集 quote_snapshot，并非直接生成分钟 OHLC；任务定义存在不代表正在执行。
3. 图表没有盘中自动刷新。现有 30 秒刷新仅覆盖新闻、邮件状态面板。
4. 分钟闭合状态、源时间与延迟提示、午休/收盘判断，以及过期行情禁止新信号。
5. 信号缺少首次确认时间、候选/已确认区分、确认后固定记录和消失/修订审计；直接重算历史极值标记不等于实时可用信号。

## 确认时间实测

锡华科技二买当前标记日期为 2026-09-14，价格 16.60。用相同输入窗口逐日递增回放：只读取到 9月14日时该信号不存在；读取到9月15日时首次出现。分型需要右侧 K 线确认，因此历史极值日期和可获知日期不同。当前 API 只输出 date，没有 confirmed_at；图形把标记画回极值日期，用户无法看出确认延迟。

此外，页面“中枢个数 / 笔数”实际第二项是信号数；“信号数为近5日实测落库口径”与返回多月历史且即时计算的实际行为不符。“置信”数值来自引擎规则，不是经验证的成功率。

## 建议接通顺序

先完成自选/持仓分钟采集与延迟验证，再接入周期图表；信号按已闭合 K 线逐步计算，在首次可确认的时间显示买点观察/卖点风险提醒，同时可用不同样式标出历史结构点。最后验证交易日自动刷新、T+1可卖数量约束、同一信号不重画以及断网恢复，不把未来信息提前显示。分时价格线与分钟蜡烛 K 线应提供明确切换。
